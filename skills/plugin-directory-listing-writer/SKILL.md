# Plugin Listing and Documentation Writer

1. Read manifests and inventory packaged features first.
2. Describe actual user outcomes, workflows, dependencies and material limitations.
3. Prefer concrete verbs; avoid unverifiable performance claims.
4. State runtime compatibility precisely; do not infer verified publisher identity from a username.
5. Use accurate public URLs and policies only; never invent legal/support pages.
6. Write prompts for distinct user jobs.
7. Include beginner install, use, update/uninstall and troubleshooting for installable projects.
8. Distinguish documented steps from tested steps.
9. Track missing metadata, unsupported claims and character limits.

Output exact metadata, validated counts, asset paths, prompts, documentation status and unresolved limitations.
