# Plugin Experience Architect

1. Identify primary users, recurring jobs and finished results.
2. Group Skills by distinct outcome; remove duplicates and implementation-only features.
3. For each Skill, define trigger, required inputs, outputs, failure modes and rationale for separation.
4. Inventory DSH-native capabilities and runtime dependencies. A Skill does not grant permissions.
5. Treat read/list/search/grep as discovery; treat write/patch/delete and mutating commands as authorized state changes.
6. Keep external services optional unless the core job requires them.
7. Build concrete starter prompts spanning engineering, productivity, research, experimentation and evaluation.
8. Test direct, indirect and negative prompt examples; fix overlap by tightening descriptions.
9. Tie public promises to packaged behavior.
10. Record assumptions, target DSH version and unverified runtime risks.

Output audience/job, Skill inventory, dependencies, capability claims, mutation boundary, starter prompts, negative cases, architecture and risks.
